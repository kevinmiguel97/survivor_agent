# NFL Survivor Agent

A Claude Code-driven assistant for a private/office NFL survivor pool.

**Pool rules assumed:** pick one team per week; each team may be used only once all season; one loss eliminates you from the main prize; after elimination you keep picking every remaining week (no team reuse) to try to finish with the fewest total losses for a "fewest mistakes" consolation prize.

## What it does

Three Claude Code skills, backed by a small set of Python scripts and a persistent `data/state.json`:

- **`survivor-pick`** — recommends this week's pick. Uses free historical/schedule data (`nfl_data_py`) plus live web research (odds, injuries, weather) to estimate win probability, and — while still alive in the main pool — weighs saving strong teams for tougher future weeks. Once eliminated, it switches to a purely myopic "best team available" strategy, since there's no more future value to protect.
- **`survivor-record`** — records your actual pick and, later, its result. This is the only thing that writes to `data/state.json`.
- **`survivor-grid`** — publishes a full-season schedule grid (all teams x all weeks) as a Claude Code Artifact, in the style of [Sharp Football Analysis's schedule grid](https://www.sharpfootballanalysis.com/analysis/nfl-schedule-grid-regular-season/), to help spot good weeks to save a strong team for.

Just ask Claude things like *"what's my survivor pick for this week?"*, *"I'm going with the Bills"*, *"the Chiefs lost"*, or *"show me the schedule grid"* — the skills trigger automatically.

## Setup

Dependencies live in a project-local virtual environment (never installed globally).

```powershell
python -m venv .venv
```

`nfl_data_py` pins `pandas<2.0`/`numpy<2.0`, which have no prebuilt wheels for modern Python — install modern pandas/numpy first, then add `nfl_data_py` without its broken pin:

```powershell
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install pandas numpy appdirs fastparquet
.venv\Scripts\python.exe -m pip install --no-deps nfl_data_py==0.3.3
```

Initialize the pool state once, at the start of the season:

```powershell
.venv\Scripts\python.exe scripts\state_store.py init --season 2026
```

This creates `data/state.json` with `current_week: 1`, `status: alive`, `mistake_count: 0`, and no picks yet.

## Repo layout

```
data/
  state.json           # your picks, results, and pool status — the source of truth
  full_schedule.json   # cached full-season schedule, generated by survivor-grid
scripts/
  state_store.py        # load/save/update state.json (also a CLI — see --help)
  fetch_week_data.py     # this week's matchups + team stats via nfl_data_py
  fetch_full_schedule.py # full season schedule for all 32 teams, for the grid
.claude/skills/
  survivor-pick/         # weekly recommendation
  survivor-record/        # record a pick / a result
  survivor-grid/           # publish the schedule-grid Artifact
```

## Manually inspecting state or data

```powershell
.venv\Scripts\python.exe scripts\state_store.py show
.venv\Scripts\python.exe scripts\fetch_week_data.py --week 1 --season 2026
.venv\Scripts\python.exe scripts\fetch_full_schedule.py --season 2026
```
